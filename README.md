# shoplazza-virtual-logistics-timeline

店匠（Shoplazza）订单详情页的物流模块，Liquid + 内联 JS 片段，整段粘进主题模板就能用。

起因挺简单：**店匠自带的 track123 查不到部分承运商的物流**，所以这里自己接了 **TRACK718** 和 **17TRACK**；顺手把"已付款但还没发货"那段空窗期补了一条订单进度时间轴。

## 文件

- `代码.txt` —— 模块全部代码，粘贴到订单详情页模板
- `操作步骤.docx` —— 后台粘贴位置、保存、测试方法（带截图）

## 大概干了三件事

**1. 未发货时：订单进度时间轴**

已付款 + 未发货时显示 7 个节点（下单 → 确认 → 备货 → 质检 → 打包 → 待揽收 → 已发货）。时间按订单时间加固定偏移算出来，同一订单每次刷新都一样，只显示已经"到点"的节点。

**2. 已发货时：真实物流查询**

店匠服务端不给运单号，所以页面加载后自己从 DOM 里抓，抓到就按承运商路由：

| 判断 | 查询平台 |
| --- | --- |
| 命中 Yanwen 标记，或前缀是 `BST / GZX / LR / ST / WBD / XY` | TRACK718 |
| 其他 | 17TRACK |

抓不到就提示用户手动粘贴单号。两个平台的外部脚本都是点查询那一刻才加载，不拖慢页面。

**3. 承运商品牌名保护**

浏览器翻译会把承运商名翻成中文，和平台上的承运商匹配对不上，所以把页面上的 `Yanwen` 包成 `<span translate="no" class="notranslate">`；组件是异步渲染的，晚渲染或重渲染都会再处理一遍。

## 关于承运商：Yanwen 只是例子

代码里的 `Yanwen` 是店里实际在用的承运商名字，**属于示例，可以替换也可以加**（不同承运商走的平台不一样，有些只有 718 有数据，有些只有 17TRACK 有）。改的时候动这几处：

- `TRACK718_PREFIXES` —— 单号前缀表，决定哪些单号走 TRACK718
- 代码里所有 `Yanwen` 字符串（品牌名保护、`vt-carrier-brand` 文案、缓存标记）
- 页面上的匹配规则（父级区域是"在物流区域内"还是"在某个承运商块内"，按店匠实际结构调）

判断思路是通用的：**品牌名 + 单号前缀**两条路决定去哪个平台查。

## 注意

- 时间轴上的时间是**算出来的，不是真实物流事件**，只用来填补未发货的空窗期，有合规要求请自行评估。
- 查询依赖第三方 `static.track718.net` 和 `www.17track.net`，运单号会发送给这两个平台。
- 时间按访客浏览器本地时区显示。
- 店匠若改了物流组件的 class 名（`.shipment-package-container` / `.shipment-package` / `id^="shipment-tracking-"`），代码里的选择器要跟着改。
